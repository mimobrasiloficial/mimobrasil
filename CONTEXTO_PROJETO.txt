1. O QUE É ESTE PROJETO
--------------------------------------------------------------------------------
Site de e-commerce de chocolate artesanal chamado "MIMO"
(slogan: "Mais que chocolate. Um momento.") — projeto de TCC.

Funcionalidades do site:
- Loja de produtos (chocolates, bombons, barras)
- Personalização de produtos ("Monte seu Mimo" — wizard guiado)
- Programa de fidelidade ("Mimo Club" — saldo, progresso, benefícios)
- Carrinho lateral (drawer)
- Checkout em 4 etapas (Dados → Entrega → Pagamento → Confirmação)
- Conta do cliente (login, cadastro, área logada, favoritos)
- Página institucional (Sobre)

5. CONFIGURAÇÃO DO FIGMA MCP NO DEVIN — OUTROS COMPUTADORES
--------------------------------------------------------------------------------
O Devin NÃO usa a nuvem para este projeto — tudo roda local via Devin Desktop.
Para configurar o Figma MCP em outro computador:

PASSO 1 — Abrir terminal e rodar (o executável devin.exe NÃO está no PATH;
usar o caminho completo):

  "C:\Users\<USUARIO>\AppData\Local\Programs\Devin\resources\app\extensions\windsurf\devin\bin\devin.exe" mcp add -s user figma-remote https://mcp.figma.com/mcp

  (-s user = configuração global, vale para todos os projetos;
   sem -s grava em .devin/mcp_config.local.json do projeto)

PASSO 2 — Autenticar via OAuth (abre o navegador):

  "<mesmo caminho>\devin.exe" mcp login figma-remote

  Na página do Figma: login na conta → Allow → redirect localhost:8765.
  Tokens ficam salvos localmente e renovam sozinhos.

PASSO 3 — Verificar:

  "<mesmo caminho>\devin.exe" mcp list

  Dentro do Devin, o agente pode chamar mcp_list_servers /
  mcp_list_tools para confirmar que figma-remote está ativo.

OBSERVAÇÕES:
  - Cada cliente MCP autentica separadamente: se já usou Figma MCP no
    Cursor/Windsurf, precisa logar de novo no Devin.
  - O Windows tem outro "devin" possivelmente conflitando — SEMPRE usar o
    caminho completo do devin.exe acima.
  - Rate limits: plano Starter tem cota de tool calls (diária).
    get_metadata NÃO consome cota da mesma forma; get_design_context,
    download_assets e get_screenshot consomem.

6. COMO O DEVIN DEVE TRABALHAR COM O FIGMA (FLUXO)
--------------------------------------------------------------------------------
Antes de gerar código de uma tela:

  1. Ler a skill obrigatória:
     MCP resource skill://figma/figma-design-to-code/SKILL.md
     (via mcp_read_resource no server figma-remote)

  2. Chamar get_design_context com:
     - fileKey: hOYTA6wFixdgxlNrEONDNE
     - nodeId: <id do frame, ex: 9:40930>
     - sessionId: valor retornado por create_session
       (criar com create_session {fileKey, description})
     - skillNames: "resource:figma-design-to-code"
     → retorna código React/Tailwind + URLs de assets + screenshot

  3. Baixar assets com download_assets (retorna rawImages JPEG/PNG
     originais + svgAssets dos ícones + export PNG da tela)

  4. Adaptar o código ao stack do projeto (NÃO copiar cegamente —
     o output é protótipo visual em React/Tailwind)

  5. get_metadata sem nodeId lista páginas; com nodeId devolve a
     árvore XML do nó (não consome cota de render — usar bastante
     para explorar sem gastar limite)

10. REGRA DO ONEDRIVE — ARQUIVOS .js (IMPORTANTE)
--------------------------------------------------------------------------------
O OneDrive da escola (SESISENAISP) NÃO permite salvar arquivos .js na pasta
sincronizada. Por isso:

- Na pasta local (OneDrive), TODO arquivo JavaScript deve ser salvo como
  .txt. Exemplo real: assets/js/main.js existe no GitHub, mas na pasta
  local está como assets/js/main.txt (mesmo conteúdo).
- No GitHub/repositório, manter SEMPRE a versão .js real — sem ela o
  site não funciona para quem clonar.
- REGRA PARA O DEVIN: sempre que for criar/editar/salvar arquivo .js
  nesta pasta, salvar como .txt e avisar o usuário. Se o arquivo já
  existir como .js no repo, a versão commitada continua .js.
- ATENÇÃO ao testar localmente: index.html referencia assets/js/main.js,
  que não existe na pasta local (só main.txt). Para preview local, será
  preciso renomear temporariamente ou ajustar a referência — alinhar
  com o usuário antes.
